# Фронтенд «ФСП Талант»

React 18 + TypeScript + Vite, компоненты Mantine 7, данные через TanStack Query. Единое веб-приложение для двух ролей: кандидат и работодатель. Работает с REST API бэкенда (FastAPI) по документации `docs/openapi/openapi.json`.

## Запуск

Нужен запущенный бэкенд (без него интерфейс покажет страницу с инструкцией).

```bash
# из корня репозитория: бэкенд и демо-данные
pip install -r backend/requirements.txt
python backend/scripts/demo_reset.py            # демо-аккаунты, пароль demo123
uvicorn backend.app.main:app --port 8000

# фронтенд
cd frontend
npm ci
npm run dev        # http://localhost:3000, запросы /api проксируются на :8000
npm run build      # проверка типов и production-сборка в dist/
```

В Docker: `docker compose -f infra/docker-compose.yml up -d --build` (интерфейс на :3000, nginx проксирует `/api` на backend). Адрес API можно задать переменной `VITE_API_URL`.

Демо-аккаунты: `anna@fsp-talent.ru` (кандидат с историей ФСП), `boris@fsp-talent.ru` (кандидат без ФСП), `recruiter@yandex.ru` и `hr@fsp-russia.ru` (работодатели). Экспресс-тест без регистрации: `/express`.

## Связь с документацией API

Типы запросов и ответов генерируются из спецификации, поэтому интерфейс и документация не расходятся:

```bash
npm run sync:api      # запущенный бэкенд → docs/openapi/openapi.json → src/api/schema.d.ts
npm run gen:api       # только types: docs/openapi/openapi.json → src/api/schema.d.ts
```

Все вызовы собраны в [src/api/api.ts](src/api/api.ts) и типизированы через `schema.d.ts`; ошибки сервера приводятся к понятному тексту в [src/api/http.ts](src/api/http.ts).

## Структура

| Путь | Назначение |
|---|---|
| `src/api/` | HTTP-клиент, типизированные вызовы API, сгенерированные типы |
| `src/auth/` | сессия (JWT в sessionStorage), защита маршрутов по роли и подтверждению почты |
| `src/hooks/` | запросы TanStack Query и ключи кэша; локальные данные анкеты |
| `src/components/layout/` | каркас кабинетов: шапка, боковое меню, адаптивный бургер |
| `src/components/common/`, `candidate/`, `employer/` | повторно используемые блоки |
| `src/pages/` | страницы кабинетов, вход и регистрация (`auth/`), материалы для экспертов `/demo` |
| `src/theme/`, `src/index.css` | палитра брендбука ФСП, тема Mantine, дизайн-токены `--fsp-*` |
| `src/utils/` | форматирование, подписи кодов API, проверка ИНН, распознавание PDF-резюме |

## Сценарии

- **Кандидат:** регистрация (или вход через ФСП ID, имитация OIDC) → подтверждение почты → анкета (форма или PDF-резюме, распознаётся в браузере) → адаптивный тест → категория → приглашения с вилкой → принятие (раскрытие контактов) или отказ; привязка ФСП ID; согласия 152-ФЗ, предпросмотр «что видит работодатель», отзыв контактов; история тестирования; задания работодателей; PDF-профиль.
- **Работодатель:** описание потребности текстом → разбор параметров → ранжированная подборка с категориями, фильтрами и объяснением по компонентам формулы → приглашение с обязательной вилкой → статусы; банк кандидатов с фильтрами; профиль компании, проверка ИНН, синхронизация вакансии из ATS.

Подробная сверка с ТЗ и ответами организаторов: [COMPLIANCE.md](COMPLIANCE.md).

## Дизайн и адаптивность

- Шрифт Montserrat подключён локально (`@fontsource/montserrat`), без внешних CDN.
- Акцентный цвет `#D6004A` - затемнённый вариант бренд-цвета `#FF0053` для контраста 5,3:1 (WCAG AA). Рамки вместо теней, скругление 4–6 px.
- Раскладка проверена на ширинах 320–1920 px: боковое меню сворачивается в бургер на ширине меньше 992 px, таблицы прокручиваются внутри карточек, модальные окна на телефоне занимают весь экран, на сенсорных устройствах область нажатия не меньше 44 px.

## Ограничения текущей версии API

Фронтенд использует только существующие эндпоинты бэкенда. Чего не хватает:

- нет списка открытых вакансий и сохранения отклика (`POST /needs/{id}/apply` заглушка), поэтому самостоятельный отклик кандидата и публикация вакансий работодателем с откликами в интерфейсе не показаны (метод `api.applyToNeed` готов);
- `PUT /me/profile` не хранит опыт, стек, soft-skills, роли и «о себе»: эти поля анкеты сохраняются только в браузере кандидата (`src/hooks/useExtras.ts`);
- поля «направление деятельности» и «контакты» компании в API отсутствуют;
- параметры `/search/candidates` (кроме ФСП) используются сервером только для сортировки, поэтому банк кандидатов фильтрует результат на клиенте; максимум `limit` - 100;
- вакансия, синхронизированная из ATS, не сохраняется как потребность (подбор по ней отвечает 404), экспорт кандидата в ATS возвращает 500;
- сервер не запрещает повторные приглашения одному кандидату (в интерфейсе кнопка блокируется).
