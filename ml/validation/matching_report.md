# Валидация механики подбора

Сгенерировано `ml/validation/matching_eval.py` (seed 2026). Воспроизводится командой `make validate-matching`.

## Главное

- FSP-Talent − BM25: Δ nDCG@10 +0.101 [+0.031; +0.170] — выше, разница значима.
- FSP-Talent − заявленная категория + BM25: Δ nDCG@10 -0.007 [-0.064; +0.047] — разница незначима.
- Подобранные веса − исходные: Δ nDCG@10 +0.105 [+0.063; +0.148] — выше, разница значима.
- Подобранные веса − заявленная категория + BM25: Δ nDCG@10 +0.098 [+0.044; +0.151] — выше, разница значима.
- С целевым банком заданий: FSP-Talent − заявленная категория + BM25 Δ nDCG@10 +0.041 [-0.022; +0.102] — разница незначима.
- Вариант «Без теста (T = 0)» лучше полной формулы на +0.057 nDCG@10: при текущих весах эта часть формулы мешает.
- Вариант «Без ФСП (F = 0)» лучше полной формулы на +0.040 nDCG@10: эталон учитывает только соответствие вакансии, а ФСП по ТЗ — бонус внутри категории, так что небольшая цена ожидаема.
- Вариант «Без категории (C = 0)» лучше полной формулы на +0.030 nDCG@10: при текущих весах эта часть формулы мешает.
- Вариант «Без веса подтверждения навыков» лучше полной формулы на +0.041 nDCG@10: ложных среди непроверенных навыков в профилях 27.7%, а скидка 0,3–0,5 рассчитана на гораздо большую долю.
- Вклад T зависит от точности теста: убрать T выгодно на +0.057 при текущем банке, но только на +0.005 с целевым банком, если работодатель ценит силу внутри грейда. Вес T = 0,25 завышен для нынешней точности теста.
- Кандидаты без ФСП не вытесняются: в 97.0% пар релевантный кандидат без ФСП стоит выше нерелевантного с ФСП.
- p95 времени подбора 61 мс на 1000 кандидатах.

## Постановка

- Синтетический мир: 1000 кандидатов, 50 потребностей (10 написаны вручную, остальные по шаблонам), 20 компаний. Потребности поделены на dev (26) и test (24) поровну внутри каждой специализации: веса подбираются только на dev, все итоговые цифры — на test.
- Эталон релевантности 0–3 строится только по скрытым атрибутам: истинная специализация, истинный грейд и навыки, которыми кандидат реально владеет. Ни одна система их не видит.
- Все системы видят одно и то же: анкету, заявленный грейд, результат теста (реальный CAT-движок на текущем банке заданий), навыки с источником подтверждения, достижения ФСП, текст резюме. Жёсткие условия работодателя (формат, город, бюджет, скрытые профили) одинаковы для всех систем.

| Релевантность | Та же специализация | Другая специализация |
|---|---|---|
| 3 | грейд совпадает, стек освоен на ≥ 75 % | — |
| 2 | грейд совпадает и стек 50–75 %, или соседний грейд и стек ≥ 75 % | — |
| 1 | остальные сочетания с грейдом ±1 | грейд ±1 и стек ≥ 75 % |
| 0 | грейд отличается на 2 и больше, или соседний грейд и стек < 50 % | иначе |

Релевантным для P@10, MRR и Recall@50 считается уровень ≥ 2; nDCG@10 использует все уровни.

Свойства мира, которые влияют на результат:
- грейд подтверждён тестом у 97.2% кандидатов; подтверждённый грейд совпадает с истинным у 69.8%, заявленный самим кандидатом — у 79.6%;
- история ФСП у 36.6%, корреляция FSP-score с истинной θ 0.28 (слабая по плану);
- резюме загружено у 70.1%, накрутка ключевых слов в резюме у 16.2%; среди навыков из резюме и анкеты ложных 27.7%.

## Ограничения

- Данные синтетические, а эталон релевантности задан формулой: цифры показывают, как механика ведёт себя при принятых допущениях, а не на реальном рынке. Экспертная разметка (`--export-annotation`) проверяет сам эталон.
- Тест подтверждает грейд реальным движком на текущем банке, поэтому качество подбора зависит от наполнения банка (см. отчёт `cat_sim_report.md` и вариант с целевым банком выше).
- BM25 без стемминга: для русского текста это ослабляет базовую линию по описаниям, но навыки в вакансиях и резюме записаны одинаково.
