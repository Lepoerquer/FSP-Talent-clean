# ADR 004: API-First подход и версионирование контрактов

## Статус
Принято (Accepted)

## Контекст
Для обеспечения слаженной параллельной работы разработчика платформы (Р1), разработчика фронтенда (Р3) и ML-инженера (Р2) необходимо устранить рассинхронизацию форматов данных и контрактов эндпоинтов на самых ранних стадиях. Фронтенд должен иметь возможность генерировать строгие TypeScript интерфейсы непосредственно из спецификации API.

## Решение
1. **Единая спецификация OpenAPI 3.1:**
   - Спецификация генерируется автоматически из Pydantic v2 схем FastAPI и экспортируется в `docs/openapi/openapi.json`.
   - Swagger UI и ReDoc доступны по стандартным адресам `/docs` и `/redoc`.
2. **Версионирование эндпоинтов:**
   - Все публичные методы группируются под префиксом `/api/v1`.
3. **Группы контрактов:**
   - `/api/v1/auth/*` - регистрация, получение токенов, подтверждение почты.
   - `/api/v1/dictionaries/*` - направления, специализации, грейды, навыки, синонимы.
   - `/api/v1/me/*` - операции кандидата: анкета, резюме, согласия, настройки приватности, статус грейда.
   - `/api/v1/assessments/*` - сессии тестирования: `start`, `next`, `answer`, `finish`, `result`.
   - `/api/v1/needs/*` - создание потребности работодателя, разбор текста, получение объяснимых рекомендаций кандидатов.
   - `/api/v1/invitations/*` - создание приглашения с валидацией зарплаты `salary_from <= salary_to`, переходы FSM (`view`, `accept`, `decline`, `withdraw`).
   - `/api/v1/candidates/*` - публичный анонимизированный просмотр и детальный просмотр раскрытого кандидата.
   - `/api/v1/fsp/*` - привязка ФСП ID, запрос достижений и расчет скора.
   - `/api/v1/demo/*` - сервисные демонстрационные методы для жюри (`vacancy-to-test`, сброс демо-данных).
4. **Контракт ошибок:**
   - Стандартизированный JSON формат ответов об ошибках:
     ```json
     {
       "error_code": "INVITATION_SALARY_REQUIRED",
       "message": "Приглашение обязательно должно содержать зарплату 'от' и 'до' в рублях",
       "details": {}
     }
     ```

## Последствия
- Р3 может запускать генерацию типов и мокать ответы до завершения полной имплементации бэкенда.
- Тесты API гарантируют соблюдение контракта и валидацию входных данных на уровне Pydantic.
